# 검증 기록

2026-09-19, macOS Python 3.14.3에서 로컬 검증했다. NVIDIA GPU 및 PyTorch는 이 로컬 환경에 없다. 사용자 Ubuntu 결과와 로컬 검증을 구분하며 최신 검증은 v5 절을 따른다.

## v5 검증

- 업로드된 v4 ZIP과 추출본 84개 파일, SQLite integrity·빈 WAL, DB/JSONL 253행, manifest의 13개 실행 소스 hash와 v4 배포본, 작업 목록·순서·digest를 대조했다. 일반 측정 246개의 저장된 정확성 검사, 7블록 통계·판정·처리량·연결 잔차가 일치했다. 원자료는 변경하지 않았다.
- NCU 4건의 커널 metric, NSYS 2건의 커널 각 80개를 확인했다. 마지막 Graph NSYS의 SQLite에는 graph trace 21행(양의 시각 20행), 개별 커널 0행이 있다. 마지막 FAIL은 추적 단위와 요구한 커널 보고서가 맞지 않는 문제이며 CUDA 계산 실패를 입증하지 않는다.
- NSYS node 추적 옵션과 실제 커널 CSV 검사, stats 종료 코드 기록을 추가했다. 헤더만 있는 결과, SKIPPED, 비유한·0 metric과 0 instances, stats 실패는 계속 거부한다. 업로드된 실제 NSYS CSV 2건은 통과하고 Graph SKIPPED 1건은 거부한다.
- 로컬 회귀 검사 23개를 통과했다. manifest 불일치 차단, 실패 시도 보존, 새 NSYS 검사와 명령 전달을 포함한다.
- 프로토콜 3: 조건별 관측 안정화 3,000 ms. 초기 예열 180초, 7블록, 100 ms 목표와 5% 변동 기준은 유지한다. pressure 블록 시작 시각을 추가했다. v4의 변화가 큰 블록은 삭제하지 않는다.
- v5 GPU 실행과 개선 효과는 미확인이다. 새 `pilot_v5`가 필요하며, v4는 253작업 기록·FAIL 1·REVIEW 8·round 변동 9묶음이므로 풀 스윕을 승인하지 않았다.

## v4 검증 (작성 당시 이력)

- 사용자 ZIP의 SQLite·JSONL 247행, manifest와 실행 소스 13개의 hash, 결과 digest, 246개 일반 측정의 7블록 통계·처리량·연결 잔차를 재계산해 일치를 확인했다. 일반 측정의 저장된 정확성 검사는 모두 통과했고, REVIEW 3개와 round 간 변동 15묶음은 남아 있다.
- 첫 Nsight Compute의 실제 종료 코드 0, `.ncu-repz` 보고서와 696열 raw CSV를 확인했다. 기존 `.ncu-rep` 경로 가정과 `Metric Name` 열 검사 때문에 잘못 FAIL로 분류됐음을 재현했다. 업로드된 실제 CSV는 수정한 검사에 통과한다. 원본 FAIL 기록은 변경하지 않았다.
- 표준 라이브러리 unittest 21개 통과. 두 NCU 보고서 확장자, 넓은/긴 CSV 형식, 쉼표를 포함한 이름·숫자, 헤더만 있는 출력·비유한 metric·빈 보고서·비정상 종료 거부, 재시도별 보고서 보존, 짧은 블록 판정 경계와 반복 수 보정의 여유를 추가 검증했다.
- 초기 예열 10→180초, 블록 보정 90~110% 목표 범위로 변경했다. 개별 조건 settle 750 ms, 7블록, 변동 5% 및 수치 오차 기준은 유지했다. 프로토콜 버전은 2이며 새 결과 폴더가 필요하다.
- NVIDIA GPU에서 v4 재실행은 아직 수행하지 않았다. 추가 예열의 효과, 나머지 NCU 3작업과 Nsight Systems 3작업의 실제 완료를 새 파일럿에서 확인해야 한다. 21개 로컬 검사를 GPU 검증 완료로 해석하지 않는다.

## v1~v3 검증 이력

- 표준 라이브러리 unittest 18개 통과. 조건 재현성·ID 중복, 새 holdout 격리, 형상별 split, 입력 seed, dtype 순서 교대, 관측된 안정화 시간, 재보정, IQR/drift, 중단된 DB transaction, 재시작·실패 이력, 수동 파일럿 확인, 코드/환경 불일치 차단, 잠금, 비유한 진단값 및 보고서 내보내기를 검사했다.
- Python 파일 컴파일과 Bash 구문 검사를 통과했다.
- v2에서 원본 `run_research_checked.sh`를 연결했다. 원본과의 SHA-256 일치, 셸 파일의 코드 fingerprint 포함, 가짜 래퍼를 이용한 호출 전달·공백/상대경로·기본 실행·종료 코드 0/2/17 보존 검사를 통과했다. 사용자가 제공한 2026-09-19 GPU 실행 로그에서 기존 래퍼와 새 환경 검사를 통과한 뒤 프로세스 검사에서 중단된 것을 확인했다.
- `plan pilot`: 253작업. 주 측정 96, 대조 128, 연산 기준 8, 대역폭 2, 연결 12, 프로파일링 7이다.
- `plan full`: 42,490작업. 주 측정 36,012, 대조 5,256, 경계 450, 연산 기준 18, 대역폭 9, 연결 702, 프로파일링 43이다.
- 주 측정은 6,002형상이다. 기존 5,000형상, 기존 목록 밖의 파일럿 형상 2개, 새 확인용 1,000형상을 포함한다. dtype 2개와 3 round를 곱해 36,012작업이 된다.
- 형상 분할은 development 219, legacy train 3,348, validation 717, 이미 탐색한 legacy test 718, fresh holdout 1,000이다. 이 개수는 실측 결과가 아니라 사전 생성 목록이다.

GPU에서 아직 확인하지 않은 항목은 CUDA Event 실제 시간, dtype별 CPU FP64 대조 통과 여부, Graph capture/replay, Nsight 버전·권한·출력 형식, 실제 안정성 및 전체 소요시간이다. 첫 파일럿에서 확인한다. 본측정 실행 완료나 성능 향상을 주장하지 않는다.

- v3는 사용자 오류의 세 데스크톱 프로세스 행을 재현해 허용되는지, 실제 Python 작업·유사 이름의 다른 경로가 계속 차단되는지, 잘못된 조회 결과를 빈 GPU로 오인하지 않는지 검사했다. GPU에서 수정 후 파일럿을 재실행한 결과는 아직 없다.
