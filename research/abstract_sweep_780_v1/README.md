# 초록용 200형상 GEMM 수집 — 780 MHz

기존 전수 계획에서 형상만 우선 선정한다. 코어 780 MHz, 메모리 6801 MHz, 기존 전력 한도 70 W에서 200형상 × FP16/FP32 × allocate/prealloc/Graph × 세 round = **3,600측정, 25,200블록, 1,200묶음**을 수집한다. 전력 한도는 바꾸지 않는다. 예열180초, 안정화3000 event ms, 100 ms 목표7블록, 정확성 검사, 5%기준은 기존과 같다.

## 실행

ZIP의 abstract_sweep_780_v1 폴더를 Ubuntu의 /home/eu/gemm-research/scripts/ 아래에 둔다. 기존 fixed_sweep_780_v1과 이전 의존 폴더를 유지한다. 이미 검토한 check 결과인 fixed_sweep_780_v1/runs/check_780도 그대로 있어야 한다. 환경을 재설치하지 않는다.

```bash
bash /home/eu/gemm-research/scripts/abstract_sweep_780_v1/launch.sh
```

현재 tmux 세션·창을 그대로 쓴다. 새 tmux 세션·창을 만들지 않는다. tmux 밖이면 현재 터미널에서 실행하고 완료까지 SSH 연결을 유지한다. tmux 안에서는 Control+B를 누르고 손을 뗀 뒤 D로 분리할 수 있다. Command+D가 아니다.

먼저 소스검사 PASS와 tasks=3600, triplets=1200이 보인다. 기존 ai_env에서 검토 완료된 60측정 check를 원래 분석기로 다시 검사하고, 검토한 manifest와 결과 digest가 일치해야 클럭 설정으로 넘어간다. 새 별도 check를 반복할 필요는 없다. 다른 GPU 작업이 돌고 있으면 중단하며 강제로 종료하지 않는다.

`Worker log:` 줄 이후 진행 상황은 표시된 파일에 기록된다. 처음180초는 예열이고 이어서 [1/3600]처럼 진행된다. 다른 SSH 터미널에서 `tail -n 20 -f '표시된 worker_0.log의 전체 경로'`로 확인한다. 여기서 Ctrl+C는 로그 보기만 끝낸다. 측정 터미널에서는 실행을 중단하므로 구분한다.

이번 점검의 평균속도로 측정약3.9시간, 준비·검산 여유를 포함한 계획예산5~6시간이다. 형상 구성에 따라 달라지는 추정치이며 완료시간 보장은 아니다. 시작/재시작 때 여유디스크20 GiB를 확인한다. 실행 중 다른 GPU 부하와 절전·재부팅을 피한다.

## 선정 기준

선정 함수는 형상과 기존 split만 읽는다. 기존 full 주 측정의 fresh_holdout을 제외한 5,002형상에서 다음32개 층을 구성한다.

- 연산량 2MNK: 2^24 미만 / 2^24~2^28 미만 / 2^28~2^32 미만 / 2^32 이상.
- 종횡비: max(M,N,K)/min(M,N,K)가4 미만 / 4 이상.
- 정렬: 세 차원 모두8의 배수 / 그 외.
- 경계: 어느 차원이64,128,256,512,1024,2048,4096 중 하나에서 거리1 이내 / 그 외.

각 층에서6~7개를 뽑으며 총200개다. 64~4096의 정육면체7개와 세 방향의(64,64,4096)형상3개는 기하학적 기준점으로 포함한다. 나머지는 고정 seed=20260921의 SHA-256 순위로 선정한다. 후보수와 층별할당,200개목록은 selection.json에 고정했다. 실행 시 함수로 재생성한 목록과 대조한다. 기존 측정시간·FAIL/REVIEW·예측오차는 선정 입력이 아니다.

종전5,000형상의 결과는 이미 탐색했으므로 이 부분집합을 미탐색 예측평가셋으로 부르지 않는다. 이번780 MHz 재측정 결과를 보기 전에 기하학적 기준으로 동결한 기술통계용 표본이다. 서로 다른 strata를 비례 표집한 것은 아니므로 전체5,000형상의 평균 성능으로 단순 일반화하지 않는다. power-of-two 근방 분류는 경계 양쪽을 통제한 완전한 paired 실험과 다르다. 기존fresh holdout1,000형상은 모두 제외한다.

기존full task ID·입력 seed·shape split·round별형상순서·세방식 순서는 그대로다. 원래full의 선별형상 주 측정만 남겼으며 추가 대조/경계/연산기준 phase는 이번 목록에 포함하지 않는다. 최종 원래113,382측정 계획과 기존10,000조건의 세방식 전수 재측정 요구는 유지한다. 이번 결과를 기존full DB에 자동 합치거나 완료처리하지 않는다.

## 종료·이어하기·해석

결과 폴더는 abstract_sweep_780_v1/runs/abstract_200_780이며, 종료 후 같은 runs에 abstract_200_780_날짜_식별자.zip을 만든다. 코드·manifest·소스사본·모든시도·블록·센서·클럭해제 근거를 포함한다. 종료하면 Enter 대기 없이 현재 프롬프트로 돌아온다. **그 ZIP을 반환하면 검토한다.**

누적SW Power Cap 카운터 해석 미해결 때문에 모두 통과해도 전체REVIEW·exit2를 유지한다. 완료 확인은 recorded=3600, missing=0, FAIL=0, timed_blocks=25200, triplets_complete=1200, timing_and_sampled_clocks_pass=true 및 실제 두 클럭 해제 성공을 함께 본다. FINISHED는 worker 상태이고 컨트롤러 해제·최종 ZIP 완료와 구분한다.

Ctrl+C 또는 처리 가능한 종료신호를 받으면 기존 코드대로 worker 종료를 기다리고 클럭을 해제한다. 같은 명령·출력경로로 다시 실행하면 저장된 작업을 건너뛰며 이전시도·실패를 보존한다. 코드나 선정목록·프로토콜이 다르면 이어쓰기를 거부한다. FAIL재시도는 원인 검토 후에만 --retry-failed를 붙인다. 실행본이나 결과를 지우지 않는다.

측정값은 약100 ms블록의 호출당평균이고,50 ms요청센서는 연속 클럭이나 단일호출 스파이크를 보장하지 않는다. 세round는 기본적으로 한worker 내 반복이다. 모드차이를 순수 할당비용·CPU대기시간으로 해석하지 않는다. 이전780파일럿과 약2%실행간 차이·누적카운터 미해결을 보존한다. 예측기학습·조립실험·논문 집필은 이 실행본에서 하지 않는다.
