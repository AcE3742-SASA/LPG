# 720 MHz 전수 GEMM 스윕

검증된 720 MHz 측정기에 기존 전수 작업 목록을 연결한 실행본이다. 코어 720 MHz·메모리 6801 MHz·기존 전력 한도 70 W를 유지하며, 완료한 200형상 자료는 진입 근거로 보존한다. 전수 결과는 새 폴더에서 처음부터 수집한다.

## 실행

ZIP의 `fixed_sweep_720_v1` 폴더를 Ubuntu `/home/eu/gemm-research/scripts/`에 넣는다. 기존 `abstract_sweep_725_v1`과 이전 의존 폴더들은 그대로 둔다. 재설치는 필요 없다. 아래 완료 결과 ZIP도 원래 `abstract_sweep_725_v1/runs/`에 있어야 한다.

`abstract_200_720_recovery_20260921_20260922_024735_e61123.zip`

기존 tmux 안에서 실행한다. 기본 동작이 full이며 새 tmux 세션·창을 만들지 않는다.

```bash
bash /home/eu/gemm-research/scripts/fixed_sweep_720_v1/launch.sh
```

현재 연구 GPU에서 다른 측정이 끝나고 정리된 뒤 실행한다. 기존 공유 GPU 잠금과 프로세스 검사, 70 W 한도·환경·소스·여유 공간 확인이 적용된다. 완료한 200형상 ZIP의 SHA-256과 검토 근거가 일치해야 클럭 설정으로 넘어간다. 지원 목록에 정확한 720 MHz가 없으면 멈춘다.

## 작업 구성

| 구간 | 측정 수 |
|---|---:|
| 주 측정: 6,002형상 × 두 정밀도 × 세 방식 × 세 회차 | 108,036 |
| 실행 방식·형상 대조 | 3,942 |
| 정렬·타일 경계 | 1,350 |
| 연산 기준 GEMM | 54 |
| 합계 | **113,382** |

본 시간 블록은 793,674개다. 기존 5,000형상 × 두 정밀도의 10,000조건을 세 방식·세 회차로 다시 측정하는 90,000개가 주 측정에 포함된다. 새 holdout 1,000형상과 원래 split·입력 seed·순서도 유지한다. allocate, prealloc과 CUDA Graph를 전 조건에서 각각 수집한다. bandwidth·pressure·chain·Nsight 작업은 이 GEMM 목록에 포함되지 않는다.

기존 180초 예열, 3,000 event ms 안정화, 100 ms 목표 7블록, 세 회차, 정확성 검사와 5% 기준을 유지한다. 검토된 52조건의 Graph 묶음을 유지하고 나머지는 기존 최초 선택·저장 방식을 따른다. 시간 변동은 REVIEW로 보존하며, 클럭·순간 제한·센서 문제는 120측정 구간 검토 후 후속 수집을 차단한다. 정확성/실행 FAIL은 해당 기록 저장 후 멈춘다. 200형상 통과가 모든 전수 형상의 안정성을 보장하지 않으므로 기존 검사를 계속 적용한다.

## 진행·중단·결과

- 예상 **약 5~6일**은 720 MHz 200형상 수집 속도를 외삽한 계획값이다. 형상별 실행시간, 재시작과 검토에 따라 달라진다.
- 20초마다 `완료/113,382 (진행률) | 남음`을 표시한다. 시작은 0%이며 예열 중에는 수가 유지된다. 기존 `progress.json`만 읽고 표시용 GPU 조회나 DB 접근은 하지 않는다.
- tmux 분리는 Control+B를 누르고 손을 뗀 뒤 D다. 일시중단은 Control+C 한 번을 누르고 현재 측정 저장·클럭 해제·압축이 끝나 프롬프트가 돌아올 때까지 기다린다.
- 정상 일시중단 뒤 같은 명령으로 재개하면 이미 저장된 task와 Graph 선택을 이어간다. 품질 문제로 중단된 결과는 검토 전 재개가 차단된다. 폴더를 지우거나 기준을 바꿔 통과시키지 않는다.
- 결과·로그는 `/home/eu/gemm-research/scripts/fixed_sweep_720_v1/runs/full_720/`에 저장한다. 종료 ZIP도 같은 `runs/`에 생성되고 `RESULT_ZIP=`으로 안내된다. `/home/eu` 바로 아래에 새 실험 폴더를 만들지 않는다.
- 100%는 기록 수집 완료다. 최종 분석·클럭 해제·ZIP 생성을 기다리고 결과 ZIP을 검토한다. 누적 카운터 미해결 때문에 전체 REVIEW/종료 코드 2가 남을 수 있다.
- fresh holdout 시간은 LOCKED 파일과 원자료에 보존한다. 모델 선택이 끝나기 전에 시험 성능을 열어 조정하지 않는다. 기존 200형상 측정은 이미 살펴본 예비 자료다.

ZIP이 다른 연구 폴더에 있다면 `launch.sh full --check /home/eu/gemm-research/.../완료결과.zip`으로 위치를 지정할 수 있다. 해시는 같은 검토본이어야 한다. 선택적인 `check` 동작은 48측정 진단이며, 기본 전수 명령에 추가 진단은 필요 없다.

## 재현 확인

GPU를 쓰지 않는 소스·작업 목록 확인은 `python3 -B fixed_sweep_720_v1/run.py verify --size full`이다. CPU 검증은 `python3 -B fixed_sweep_720_v1/test_sweep.py`로 실행하며, 실제 완료 ZIP 경로를 옮긴 경우 `GEMM_TEST_PILOT_ZIP` 환경변수로 지정한다. 측정 worker·중단 정리·저장·재개 검사·분석기는 기존 구현을 재사용한다. 기존 소스 83파일과 모든 이전 결과는 변경하지 않는다.
