# 720 MHz 분리 재측정 v4

2026-10-01 승인된 3차 재측정 실행본이다. v3의 정상 111,582건과 근거를 보존하고 남은 1,800건을 다시 수집한다. 전력 제한이 직접 관측된 6개 FP32 형상의 남은 51건을 다른 1,749건과 별도 구간에 배치한다.

## 실행

기존 연구 PC의 `/home/eu/gemm-research/scripts/`에 ZIP을 풀어 `remeasure_720_v4/`를 둔다. 기존 의존 폴더와 Conda 설치를 그대로 사용한다. 입력은 v3에서 생성한 `remeasure_720_v3/runs/full_720_remeasure2_20260930_20260930_232816_56d6fb.zip`이며 SHA-256을 검사한다.

기존 tmux 터미널에서 실행한다.

```bash
bash /home/eu/gemm-research/scripts/remeasure_720_v4/launch.sh
```

입력 ZIP을 다른 곳으로 옮겼다면 `--archive /actual/path/to/result.zip`을 붙인다. 잘못된 원본은 GPU 설정 전에 거부한다. 출력은 v4의 `runs/full_720_remeasure3_20261001/`, 로그와 결과 ZIP도 연구 폴더 내부에 저장한다. 마지막 `RESULT_ZIP=`에 결과 경로가 나온다. 진행률·안내·경고·오류는 ASCII 영어다.

## 변경한 범위

다른 1,749건을 먼저 120건씩 14구간과 마지막 69건 구간에 수집하고, 문제 형상의 51건은 마지막 별도 구간에 수집한다. 총 16구간이다. 각 그룹 안에서는 원래 manifest 순서를 유지한다. 문제 형상을 뒤로 옮긴 순서와 구간 경계 변경은 새 프로토콜 설정과 `recovery/collection_schedule.json`에 기록한다. 각 실제 구간의 `collection_group.json`에는 그룹과 예정 task ID를 남긴다.

기존 task ID·입력 seed·split·Graph 설정·720/6801 MHz·70 W, 예열·안정화·시간 측정·정확성 검사는 유지한다. 분석기는 v3와 바이트 단위로 같다. 한 구간에서 전력 제한이나 클럭 이탈이 관측되면 해당 구간 전체를 REVIEW로 남기는 규칙도 그대로다. 분리는 재측정의 통과를 보장하지 않는다. 정확성·CUDA·센서·열 제한·전력 한도·GPU 환경 오류의 중단 처리를 유지한다.

v3 결과 ZIP 전체를 새 결과의 `recovery/source_run.zip`에 보존한다. 정상 111,582건은 원래 seq와 내용 및 근거 파일을 유지하고, 이전 원본과 시도는 해당 ZIP 안에서 이어서 보존된다. 누적 전력 제한 카운터 해석은 미해결 상태로 유지한다.

정상 중단 후 같은 명령을 실행하면 저장되지 않은 작업부터 이어 간다. 부분 재개에서도 일반 그룹과 문제 형상 그룹을 섞지 않는다. 완료 폴더를 재실행해도 이미 저장된 REVIEW를 다시 반복하지 않는다. 다음 재측정은 새 결과 검토 후 별도 실행본으로 준비한다.

## 로컬 검증

`test_remeasurement.py`는 기존 안전 검사, 분리된 실제 worker의 대역 실행과 부분 재개, 실제 v3 ZIP 가져오기·Graph·정상 자료 보존, 1,801가지 재개 경계, 원본·출력·잠금·변조 거부 및 정상 구간 센서 재계산을 검사한다. GPU 측정은 이 검증에 포함되지 않는다.
