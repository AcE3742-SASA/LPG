# 로컬 검증 기록

2026-09-20, macOS Python 표준 라이브러리 환경에서 확인했다. 새 GPU 실행은 아직 하지 않았다.

새 unittest 10개, 재사용한 v4 진단 검사 22개, v6 검사 33개를 통과했다. Python AST·Bash 구문 검사도 통과했다. 기존 v6 실행 소스 14개와 v5 소스 13개의 hash가 기준본과 같았다. Nsight parser 7함수, tracer·하위 프로세스 정리·압축·hash 4함수는 v4와 AST가 동일하다.

새 검사는 다음을 포함한다.

- 5단계의 조회 간격, 8개 case의 순서 교대, 같은 seed와 Graph 29/56회 고정.
- CLI CSV 열 수·timestamp·마스크·사유·카운터 파싱, 필수 클럭 누락 거부, 선택 카운터 N/A 보존.
- 블록 내부·외부 표본 분리, 내부 표본이 없을 때 보간 방지, 카운터 감소·표본 부족을 0으로 오인하지 않기.
- 요청 간격과 실제 기록 간격 구분, 역행 timestamp 거부, 센서 해상도 미검증 표식.
- Nsight 8회 반복 캡처·Graph node 명령과 profiler 시작→안정화→측정 순서.
- 원래 block 호출 수 보존, 측정 밖 host 시각 기록, 실제 worker의 고정 묶음 전달 및 정확성 실패 시 타이머 복원·monitor 정리.
- 5단계×8작업·8 SQLite·56개 NVTX 측정 범위의 합성 자료로 전체 분석. 280블록 보존과 네 조건의 두 관측 영향 비율 확인.
- 누락 trace·변경된 Graph 묶음 거부, Nsight 경고를 원문으로 보존하고 REVIEW 판정.
- 공백 경로에서 래퍼 실패 코드를 보존하고 로그가 닫힌 뒤 결과 ZIP을 만드는 셸 검사.

합성 데이터는 임시 디렉터리에서 소프트웨어 검사에만 사용한다. 실제 GPU 측정값으로 쓰지 않는다. 동일한 타이머·trace 함수를 재사용해도 새로운 두 조건의 CUDA 경로, 더 잦은 조회의 실제 영향, 센서 갱신 주기, 새로운 query 필드의 드라이버 지원과 안정성을 로컬 검사로 확인할 수는 없다.

원본 v6 파일럿의 REVIEW는 유지한다. 이 진단은 원래 192작업의 부하 이력을 전부 재현하지 않으므로 변동 비재현만으로 기존 결과를 통과 처리하지 않는다. 모든 결과를 검토한 뒤 full 여부를 결정한다.

검증 로그와 배포 파일 대조는 자율연구 `analysis/clock_audit_v1_2026-09-20/`에 보존했다. 실제 실행 안내와 비교 범위는 README.md에 있다.
