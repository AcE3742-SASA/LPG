# REVIEW 1,800건의 2차 재측정 준비

2026-09-30 사용자가 남은 1,800건을 다시 측정하지 않은 이유를 물었다. 재측정해도 통과할 수 없다고 판정한 것은 아니다. 앞선 재측정 요청을 이어받아 `remeasure_720_v3`을 준비했다. 정상 111,582건을 보존하고 남은 1,800건(일반 1,543건, fresh holdout 257건)만 다시 수집한다.

## 검증 결과

로컬 CPU 검증과 배포 검사는 PASS다. 실제 v1 반환 ZIP을 읽어 931개 정상 구간의 111,582건을 가져왔고, 기존 분석기로 센서 로그를 다시 계산한 결과도 전부 PASS였다. 미수집은 정확히 1,800건이며 회차 간 추가 플래그는 0건이다. 준비된 데이터의 gate는 미수집이 남아 있어 INCOMPLETE가 맞다. 새 GPU 측정은 아직 없다.

- 원본 ZIP과 가져온 정상 기록, seq, task ID, seed, split 및 Graph 선택 12,144개를 보존했다. 제외된 15구간과 과거 시도는 원본 ZIP 안에 남는다.
- 기존 안전·재개 검사 8개, 준비 반복 시 중복 방지, 실제 재개 경계, 실행 중 잠금, 잘못된 ZIP·출력·변조 근거 거부를 확인했다.
- 배포 ZIP의 CRC와 추출본, 의존 100파일, 전체 113,382 task 목록, ASCII 출력과 셸 구문을 확인했다. 명령 대역으로 준비 선행, 준비 실패 시 GPU 진입 차단, REVIEW 종료 코드 2와 최종 압축을 확인했다.
- 측정기와 분석기, 프로토콜, 의존 해시는 영어 출력 v2와 같다. 720/6801 MHz와 70 W, 정확성 및 시간 안정성 기준을 유지한다.

이번 원본의 마지막 120측정은 제외 대상이다. 원본 마지막 seq는 118,542지만 실제 가져온 마지막 seq는 118,422여서 SQLite의 다음 새 seq가 118,423으로 배정될 수 있다. v3은 실제 가져온 마지막 seq를 재개 경계로 쓰고 원본 마지막 seq도 별도로 보존한다. CPU 검증용 DB에 새 기록을 잠시 추가해 미수집이 1,799건으로 줄어드는 재개 검사를 통과했으며, 해당 모의 기록을 제거한 뒤 원래 1,800건과 근거 해시를 다시 확인했다.
