# 900/6801 MHz 고정 진단 결과 검토

두 형상의 측정 시간은 안정적이었다. 예열을 포함한 클럭 표본 2,067개가 모두 코어 900 MHz, 메모리 6801 MHz였고, 두 round의 시간 차이는 최대 0.148%였다. 다만 측정 블록 네 개의 클럭 표본 누락과 전력 제한 카운터의 불일치가 남아 있어 full은 보류한다.

실행 환경도 확인됐다. checked runner 로그와 측정 worker의 환경 기록, 실행 명령 모두 `/home/eu/miniconda3/envs/ai_env/bin/python`을 가리킨다. worker의 `CONDA_DEFAULT_ENV`도 `ai_env`다. 사용자가 터미널에서 먼저 활성화하지 않은 것은 이번 실행의 환경 오류로 이어지지 않았다.

8측정과 56블록이 모두 수집됐다. 저장된 정확성 검사는 각 측정에서 출력 256원소를 비교했고, 모두 허용 오차를 통과했다. 전체 출력의 오차를 검증한 것은 아니다. 상대 IQR 최대 0.0342%, 첫 블록 대비 마지막 블록 변화의 절댓값 최대 0.343%로 기존 5% 기준을 통과했다.

| 형상 / 정밀도 | 실행 방식 | round 0 (µs/GEMM) | round 1 (µs/GEMM) | 두 round 범위/중앙값 |
|---|---|---:|---:|---:|
| 1888×832×632 / FP16 | prealloc | 89.608 | 89.476 | 0.1481% |
| 1888×832×632 / FP16 | Graph | 87.812 | 87.809 | 0.0040% |
| 392×2776×80 / FP32 | prealloc | 44.745 | 44.752 | 0.0164% |
| 392×2776×80 / FP32 | Graph | 43.416 | 43.403 | 0.0291% |

각 값은 7블록의 중앙값이다. Graph의 GEMM 묶음은 각각 29회와 56회로 이전 진단과 같고, 입력 seed와 시간 분모도 대조했다. 이 결과는 한 프로세스 안의 두 round다. 새 자동 코어 대조군, 독립 세션 반복, 다른 형상의 안정성까지 확인한 결과로 확대하지 않는다. 900 MHz는 이번 진단 조건이며 최종 본측정 클럭으로 확정한 값이 아니다.

자동 판정은 PASS 4, REVIEW 4, FAIL 0이다. REVIEW 네 개는 모두 일반 prealloc의 블록 내부에 클럭 표본이 없어서 생겼다. 100 ms 간격 조회를 요청했지만 실제 간격 중앙값은 약 102 ms, 최대는 114 ms였다. 누락된 네 블록의 host 범위는 약 90.49~100.03 ms여서 102 ms짜리 두 표본 사이에 통째로 들어간 것이 원자료에서 확인됐다. 네 블록의 직전과 직후 표본은 모두 900/6801 MHz였지만, 그것으로 블록 내부의 관측을 대체하지 않는다. 나머지 52블록에는 각각 한 표본이 있다.

전력 한도는 전 표본에서 70 W였다. 기록된 전력은 전체 구간 최대 61.93 W, 실제 측정 host 범위 안의 52표본에서 46.01~61.87 W였다. 측정 내부 온도는 65~67°C다. 모든 표본의 SW Power Cap, SW Thermal Slowdown, HW Thermal Slowdown 순간 상태는 비활성이었다.

그러나 SW Power Capping 누적 카운터는 첫 표본 1,645,808,024 µs에서 마지막 1,856,598,606 µs로 210.790582초 증가했다. 두 표본의 실제 시각 차이는 211.562초다. 설정 전부터 복원 후까지 별도 `nvidia-smi -q` 기록의 차이도 211.013085초여서 CSV 열 해석만의 문제는 아니다. thermal 카운터 증가는 0이다. 전력 카운터는 423회 계단식으로 증가했으며 한 번의 증가가 최대 599,811 µs였다.

[NVIDIA 문서](https://docs.nvidia.com/deploy/nvidia-smi/#clock-event-reasons-counters)는 이 카운터를 전력 때문에 요청 클럭보다 낮춘 누적 시간으로 정의한다. 이번에는 900 MHz 유지, 순간 비활성 상태, 누적값 증가가 함께 기록됐다. 표본 사이 변화, 고정 설정에서의 드라이버 보고 방식 또는 다른 원인 중 무엇인지는 이 자료로 구분하지 못한다. 전력 제한이 없어졌다고 단정하거나 드라이버 버그로 확정하지 않는다. 카운터의 증가를 개별 블록의 정확한 제한 시간 비율로 변환하지도 않는다. 자동 gate는 순간 상태와 클럭 일치를 검사하지만, 이 누적 카운터 불일치는 별도 수동 검토 사항이다.

코어와 메모리 설정 명령, 두 해제 명령은 모두 종료 코드 0이었다. 복원 직후 조회에서 SM 2160 MHz와 메모리 7001 MHz를 관측해 900/6801 MHz 고정 상태에서 벗어났음도 확인했다. 이 값이 이후에도 유지되는 기본 클럭이라는 뜻은 아니다. 측정 프로세스는 정상 종료했고, 최종 종료 코드 2는 REVIEW를 전달한 것이다. GPU 사전 설정부터 복원까지는 약 3분 34초였다. Nsight는 실행하지 않았고, 프로세스 기록에는 기존 데스크톱 GPU 클라이언트를 보존했다.

다음 단계는 관측 누락을 줄이는 짧은 검사와 카운터 불일치 확인이다. 예를 들어 50 ms 조회를 시험하되, 더 잦은 조회가 센서 갱신 주기나 측정 비용 0을 뜻하지 않으므로 기존 100 ms 조건과의 영향도 확인해야 한다. 고정 전후의 유휴 상태와 부하 상태에서 카운터가 어떻게 증가하는지 함께 구분한다. 그 뒤 선정한 고정 조건으로 전체 파일럿을 다시 검토한다. 이번 검토에서 후속 패키지 생성이나 새 GPU 실행은 하지 않았다.
