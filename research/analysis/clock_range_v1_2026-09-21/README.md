# 코어 클럭 범위 비교 실행본 검증 — 2026-09-21

사용자는 현재 780 MHz 파일럿 시작 전에 다른 그래픽 작업을 모두 껐으며 대표 10조건으로 여러 클럭을 비교하되 900 MHz 위 후보도 포함하자고 요청했다. 기존 clock_lower_v1을 별도 clock_range_v1으로 복사해 필요한 일정·개수·기준 클럭과 문서만 바꿨다. 기존 56파일은 해시가 그대로다. 측정에 필요한 기존 의존 42파일과 입력, Graph 묶음, Timer, 5% 기준은 유지했다.

후보 순서는 780→810→840→870→900→960→1050→1200→780 MHz다. 메모리 6801 MHz, 기존 한도 70 W, 대표 10형상/dtype × allocate/prealloc/Graph × 두 round를 적용해 총 540측정, 3780블록, 180묶음을 계획한다. 마지막 780에서 앞뒤 변화를 확인한다. 모든 값은 요청 후보이며 실제 유지 여부는 미검증이다.

합성 검사 10개를 통과했다. 전체 측정 개수, 세 방식·입력·Graph 묶음, 시작/마지막 780 차이, 카운터와 시간/관측 클럭의 구분, 소스·프로토콜 변경 거부를 확인했다. 가짜 GPU 명령으로 아홉 단계의 정확한 설정 순서와 전력 변경 명령 부재, 높은 클럭 REVIEW 뒤 나머지 단계 수집, 중간 단계 실패 시 완료 원자료 보존과 후속 중단, 잠금 안의 두 클럭 해제, SIGINT 뒤 정리 완료 후 ZIP 생성을 검사했다.

배포 ZIP의 CRC와 7파일 바이트를 대조하고 별도 임시 폴더에 풀어 의존 검사와 Python AST/Bash 문법 검사를 통과했다. 테스트 로그는 clock_range_tests.log, 세부 해시는 validation.json, 기존 파일 보존 근거는 preserved_hashes.json, 원본 대비 변경은 source_changes.diff에 있다.
