# 기존 10,000조건의 새 조건 재측정 범위

사용자는 2026-09-20 기존 5,000형상×FP16/FP32의 10,000조건도 새 고정 클럭 조건에서 다시 측정해야 한다고 요청했다. 기존 자료는 보존하고 새 측정 조건의 결과를 별도 데이터로 수집한다. 현재 900/6801 MHz는 192측정 파일럿에서 더 넓게 검증할 후보이며 최종 설정이 아니다. full 실행은 파일럿 결과 검토 뒤에 결정한다.

원본 full_5000x2.csv의 10,000키와 현재 v6 full 계획을 전수 대조했다. 같은 5,000형상이 legacy_shapes.csv에 있고, 모든 10,000형상/정밀도 조합이 주 측정에 포함돼 있다. 각 키에 prealloc·Graph 두 방식과 세 round를 조합한 60,000작업이 각각 한 번씩 존재한다. 이 60,000작업은 현재 v6 전체 78,952작업 계획에 이미 포함되어 있으므로 별도 중복 수집으로 더하지 않는다. 다만 기존 v6 full 실행기는 새 클럭 제어를 적용하지 않으며, 고정 조건 full 실행기는 아직 배포하지 않았다.

| 구분 | 실제 호출 | 현재 계획의 기존 조건 포함 범위 |
|---|---|---:|
| 처음 수집한 원본 | 매 호출 출력 할당을 포함한 torch.mm(A, B) | 완료한 10,000조건 |
| 새 주 측정 prealloc | torch.mm(A, B, out=C) | 전체 10,000조건, 세 round |
| 새 주 측정 Graph | 고정 입력·출력으로 CUDA Graph replay | 전체 10,000조건, 세 round |
| 현재 allocate 대조 | 매 호출 출력 할당을 포함한 torch.mm(A, B) | 기존 조건 중 434조건, 세 round |

사용자에게 출력 할당 호출까지 전 10,000조건에서 수집할지, 현재 주 측정 두 방식으로 수집할지 확인 중이다. 답변 전에는 세 번째 방식의 전체 수집을 확정하거나 실행하지 않는다. 기존 v6과 192측정 고정 조건 파일럿 패키지는 수정하지 않았다.

새 프로토콜은 기존 원본보다 예열·안정화·반복 블록·정확성 검증과 입력 seed 방식도 달라졌다. 기존/새 결과 차이를 순수 클럭 효과로 해석하지 않는다. 새 조건 안에서는 실행 방식별 시간을 별도 열·식별자로 유지하며 기존 시간과 합쳐 하나의 정답으로 사용하지 않는다.

근거는 원본 scripts/gemm_pilot.py의 timed_block, full_5000x2.meta.json, 현재 gpu_sweep_v6/plan.py 및 measure.py이며, 전수 대조 결과와 CSV 해시는 coverage.json에 있다.
