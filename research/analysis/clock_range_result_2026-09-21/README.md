# 780 MHz 파일럿과 780–1200 MHz 비교 결과

2026-09-21에 받은 두 결과 ZIP을 기존 분석기로 재계산했다. 두 실행 모두 수집과 코어·메모리 고정 해제 명령까지 완료됐다. 총 732측정·5124블록에 누락·중복이 없다. 전체 종료 코드 2는 REVIEW 판정이며, 실제 GPU worker 10개는 모두 정상 종료했다.

## 판단

**현재 연구 기준은 사용자가 선택한 780 MHz·메모리 6801 MHz·70 W를 유지하는 것을 권고한다.** 780은 24형상 파일럿의 시간·관측 클럭 기준을 통과했다. 대표 10조건에서는 840까지 통과했지만, 780 대비 시간 단축은 중앙값 1.63%이고 아직 24형상 검증은 없다. 870부터는 순간 전력 제한이 관측됐고 일부 측정에서 목표 클럭을 유지하지 못했다.

780의 통과는 이번 파일럿 범위에 한정된다. 누적 전력 제한 카운터의 해석 문제, 별도 실행 간 약 2% 시간 차이는 남아 있다. 원본의 `REVIEW`, `validated_for_full=false`, `full_sweep=HOLD`는 그대로 보존했다. 이번 검토에서 본수집이나 새 GPU 실험을 실행하지 않았다.

## 클럭 비교: 840까지 통과, 870부터 전력 제한 관측

780→810→840→870→900→960→1050→1200→780 순서다. 각 단계는 대표 10형상/dtype 조합 × allocate/prealloc/Graph × 두 round = 60측정이며, 전체 540측정·3780블록·180묶음이다. 설정 전부터 해제 후까지 62분 40초가 걸렸다.

SM 범위는 측정 블록의 호스트 시간 경계 내부 표본 기준이다. 예열 등을 포함한 worker 전체에서는 870 단계에 840 MHz도 있었다. 모든 단계의 메모리는 6801 MHz, 전력 한도는 70 W였다. SW/HW thermal 활성은 전 단계 0표본이고, 최대 관측 온도는 74°C다. 순간 전력 제한 표본 수를 제한 지속 시간으로 환산하지 않는다.

870에서 처음 문제가 드러난 조건은 **(1999,646,425) FP32, round 0**이다. allocate와 Graph는 855 MHz·Power Cap 활성이 함께 관측됐고, prealloc은 870 MHz가 관측됐지만 Power Cap이 활성화됐다. 따라서 누적 카운터의 해석 문제만으로 870의 REVIEW를 설명할 수 없다.

전체 측정별 REVIEW는 95개다. round 간 차이까지 포함한 검토 목록은 101행으로, 두 수는 집계 기준이 다르다. 1200의 최대 round 차이는 같은 FP32 조건의 allocate 240.980→194.370 µs다. 높은 클럭에서도 7블록 내부의 IQR은 작을 수 있지만 두 round의 수준 자체가 달라질 수 있다. 실제 관측 주파수가 요청값에서 벗어난 결과를 해당 고정 주파수의 성능으로 취급하지 않는다.

## 840의 이득과 별도 실행 간 차이

각 조건·방식의 두 round 중앙값을 구한 뒤 같은 키끼리 비교했다. 아래 중앙값은 30개 조건/방식의 변화율 중앙값이며, 실제 모델 실행 비중으로 가중한 성능 향상률이 아니다. 음수는 시간 단축이다.

| 비교 | 최소 변화 | 변화율 중앙값 | 최대 변화 |
|---|---:|---:|---:|
| 810 / 처음 780 − 1 | −0.4546% | −0.0555% | +0.0143% |
| 840 / 처음 780 − 1 | −2.7950% | −1.6275% | −0.4214% |

처음·마지막 780의 같은 30개 키 변화 절댓값은 최대 0.0647%다. 긴 비교 실행 안에서 기준점이 돌아온 결과는 좋다. 그러나 클럭 순서가 고정된 실험이므로 시간·실행 순서 효과를 완전히 분리한 인과 추정은 아니다.

별도로, 이번 24형상 780 파일럿과 비교 실행의 780을 공통 10조건 × prealloc/Graph의 20키로 맞췄다. round별 입력 seed와 Graph 묶음 수가 같음을 확인했다. 비교 실행 처음 780의 시간은 파일럿보다 **1.6225–2.1673% 길었고 중앙값은 +1.9010%**다. 마지막 780도 +1.6158–2.1580%다. 실행별 구성·순서·상태가 다르므로 원인은 확정하지 않는다. 작은 실행 내부 IQR과 시작/종료 기준점 일치만으로 별도 실행 간 차이가 없다고 할 수 없다.

840에서 allocate/prealloc 차이 절댓값은 10조건의 두 round 중앙값 기준 최대 0.1166%다. 64³ FP16의 Graph는 prealloc보다 26.62% 짧았다. 이는 예열·반복 블록과 캐싱 할당자 조건에서 관측한 실행 방식 차이다. 순수 CPU 대기·할당 비용이나 한 번의 Python 호출 비용으로 해석하지 않는다. **일반 torch.mm도 전수로 측정한다는 사용자 결정은 그대로 유지한다.**

## 남아 있는 카운터 문제와 관측 한계

780 파일럿의 누적 SW Power Cap은 762,717,420 µs 증가했지만 순간 활성 표본은 0개였다. 측정 블록 내부의 비활성 표본 사이에서도 카운터 증가가 확인된 창이 102개이며, 표본 간격보다 큰 증가량도 있다. 클럭 비교에서도 이런 카운터 이상을 295블록에 보존했다. 해석은 미해결이며 이를 제한 시간 비율이나 확정된 드라이버 버그로 쓰지 않는다.

50 ms 요청에 대한 실제 조회 간격 중앙값은 약 52 ms였다. 표본은 연속 관측이나 커널 유효 주파수가 아니며, 약 100 ms 블록의 GEMM 평균은 단일 호출의 스파이크 분포가 아니다. 각 실험의 두 round와 같은 밤의 후속 실행만으로 독립 세션 재현성을 확정하지 않는다. 사용자는 다른 그래픽 작업을 파일럿 시작 전에 껐다고 보고했다. 이번에도 높은 후보의 제한이 관측됐다는 사실은 확인되지만, 과거와 비교해 그래픽 작업 종료의 효과를 인과적으로 분리한 실험은 아니다.

## 보존·재현 및 다음 작업

780 유지가 권고안이며 사용자 설정을 임의로 840으로 바꾸지 않았다. 840을 채택하려면 먼저 더 넓은 형상·세 방식의 파일럿을 확인해야 한다. 본수집 준비 시에는 기존 10,000조건을 포함한 대상 전 조건에 allocate/prealloc/Graph를 각각 넣고, 기존 434조건 allocate 대조에 머물러 있는 코드의 범위·중복·작업 수·예상 시간을 다시 검산해야 한다. 현재 결과는 본수집 완료나 전 조건의 고정 클럭 유지 보증이 아니다.
