# 750 MHz 연산 천장: 커널 후보 비교

2026-09-21 사용자가 본측정에서도 780 MHz의 변동을 관찰했다고 알리고 750 MHz로 변경하도록 지시했다. 이 비교의 목표는 SM 750 MHz·메모리 6801 MHz·기존 한도 70 W다. 750 MHz의 모든 형상 안정성이나 최종 천장이 검증됐다는 뜻은 아니다.

기존 780 MHz 비교 스크립트를 재사용했다. FP32 SIMT 8개와 FP16 입출력·FP32 누산 Tensor Core 8개를 8192³에서 한 번씩 비교한다. 커널·배치·입력·검증·예열·내부 반복 조건은 같고, 출력 폴더·클록 설정·부하 판정·목표 메타데이터를 750 MHz로 맞췄다. 공유 GPU 잠금과 계산 프로세스 검사 뒤 설정하며 무부하 클록은 목표와 같아야 한다고 요구하지 않는다. 종료 시 고정은 유지한다.

기존 GPU 측정이 끝나고 정리된 뒤, 이 폴더의 `cutlass_750_kernel_compare.sh`만 Ubuntu `/home/eu/`로 옮겨 실행한다.

```bash
bash /home/eu/cutlass_750_kernel_compare.sh
```

16개 PASS·종료코드 0이 통과 기준이다. 실패하면 후속 커널을 중단하고 로그를 압축한다. 마지막에 출력되는 tar.gz를 전달한다. 약 3–5분은 이전 780 MHz 두 커널 실행에 기초한 예상이다. 다른 실험의 GPU 잠금이 있으면 설정을 바꾸기 전에 종료코드 2로 중단한다.

780 MHz 원자료와 스크립트는 그대로 보존했다. 기존 BabelStream 261.2 GB/s와 CUTLASS 6.43/39.27 TFLOP/s는 780 MHz 관측값이며 750 MHz 결과에 섞거나 클록 비례로 환산하지 않는다. 메모리 클록이 같아도 대역폭을 같다고 확정할 수 없으므로 BabelStream도 750 MHz에서 다시 측정한다. 이번 비교 이후 후보별 크기·독립 반복 확인을 거쳐 최종 천장을 결정한다.

`python3 -B test_compare.py`의 5개 로컬 대역 실행이 통과했다. 16개 커널·정확한 배치, 750/6801 설정 요청, 무부하 210/405 허용, 부하 750 허용·옛 780 거부·잘못된 메모리 거부, 검증/배치 실패 시 중단, 로그 압축·모니터 종료를 확인했다. 원격 GPU 실행이나 실제 설정 변경은 하지 않았다.
