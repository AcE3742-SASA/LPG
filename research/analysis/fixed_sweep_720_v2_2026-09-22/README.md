# 720 MHz 클럭 이탈 표시 후 계속 수집: v2 검산

사용자는 v1 풀 스윕이 이미 실행 중이라고 보고했고, SSH 재접속 부담 때문에 클럭 문제가 있는 구간을 표시하고 계속 수집하도록 요청했다. 원격 v1은 수정하지 않고 별도 v2 ZIP을 준비했다. 실제 원격 중단, 이관, v2 GPU 실행은 아직 하지 않았다.

- 정확한 코어 720 MHz, 메모리 6801 MHz와 전력 한도 70 W, 113,382측정 및 측정 함수는 유지했다.
- 클럭 이탈과 순간 SW power-cap은 해당 구간 전체에 REVIEW를 기록한 뒤 수집을 계속한다. 표본이 확인된 구간은 최대 120측정이며 이탈을 정상으로 바꾸지 않는다.
- 정확성/실행 실패, 데이터 검증 오류, 센서 누락/중단, 열 제한, 전력 한도와 환경 불일치는 계속 중단한다.
- 기존 review CSV에 구간별 표식을 반영하고 `remeasure_tasks.json`에는 시간값 없이 재측정 task를 저장한다. 전체 CSV에는 검토 대상도 보존하므로 학습 자료에서는 검토 목록을 제외해야 한다.
- 진행률은 20초 간격이며 완료된 구간의 검토 대상 수를 함께 표시한다. 종료 후 회차 간 검토와 구분한다.
- v1을 정상 중단하고 클럭 해제/압축이 끝난 뒤 자동 이관한다. 원본과 출력 폴더를 분리하고 이관 중 원본의 두 잠금을 유지하며 원본 manifest, 소스, 해시 목록과 변경 이력을 보존한다.
- 합성 전체 manifest의 저장된 3측정을 원본 변경 없이 이관해 113,379개 남음과 검토 3개를 확인했다. 이관 재실행은 중복하지 않았고 실행 중인 원본, 변조한 소스, 잘못된 해제 증거를 거부했다.
- 실제 worker 제어 흐름에서 클럭 이탈 구간 뒤 정상 구간을 수집하고 중단 후 재개해도 표식을 유지했다. 센서 누락과 정확성 실패는 후속 수집을 중단했다. GPU와 시계만 시험 대역을 사용했으며 센서 분석/DB 저장은 실제 코드였다.
- 로컬 20검사와 ZIP 추출본 20검사 PASS. Bash 구문, ZIP CRC와 파일 9개 바이트 일치, 기존 의존 91파일 및 완료 예비 원자료 3,936파일의 해시 보존을 확인했다.
- 전체 task 목록, split, 입력 seed와 측정 프로토콜은 기존 full과 동일하다. 원본 v1 배포와 실행 코드는 보존했다.
