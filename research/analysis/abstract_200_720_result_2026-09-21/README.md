# 720 MHz 200형상 본측정 검토 — 2026-09-21

**3,600측정 중 1,800개를 저장한 뒤 메모리 6800 MHz 표본 하나로 자동 중단됐다.** PASS 1,799·REVIEW 1·FAIL 0이다. 코어 저하·순간 전력 제한은 관측되지 않았다. 이번 메모리 표본은 본 시간 블록 안에 있어 앞선 예열 중 사건과 구분한다.

## 수집 범위와 품질

- 첫 회차는 200형상 모두, 두 번째 회차는 100형상을 기록했다. 세 번째 회차는 없고 세 회차 완성 조건은 0개다. 1,800측정·12,600블록·600개 세 방식 묶음이며 1,800측정이 미수집이다.
- 저장된 수치 정확성 검사 1,800건은 설정 범위에서 모두 통과했다. 전체 출력 비교 12건·표본 비교 1,788건이다. 원본 DB의 PASS는 센서 사후 판정과 별개이며 최종 분석에서 한 건이 REVIEW다.
- 최대 상대 IQR 0.48%, 절대 첫/마지막 드리프트 0.63%다. 두 회차가 있는 600개 형상·정밀도·방식 조합의 최대 범위/중앙값은 1.7%다. 모두 기존 5% 시간 변동 기준 이내이나 전체 200형상의 세 회차 재현성을 의미하지 않는다.
- 136,907센서 표본 모두 코어 720 MHz·설정 한도 70 W다. 순간 software power cap 및 software/hardware thermal slowdown 활성 표본은 0개다. 전력 범위는 약 21~67 W, 온도는 32~65°C다.
- 메모리는 136,906표본이 6801 MHz이고 한 표본만 6800 MHz다. 누적 카운터 해석 미해결 900/12,600블록은 별도로 유지하며 실제 제한 시간 비율로 환산하지 않는다.
- worker는 약 2시간 실행한 뒤 KST 21:36:36에 ERROR·exit 1로 종료했다. 코어·메모리 고정 해제 명령은 모두 성공했다.

## 중단 원인

이상 표본은 **21:35:07.870**, 1777번째 측정 `(M,N,K)=(2048,4096,256)` FP16 prealloc의 두 번째 회차에서 관측됐다. 7개 본 시간 블록 중 다섯 번째 블록(인덱스 4)에 겹친다. 바로 앞뒤 센서 표본은 6801 MHz이고 당시 코어는 720 MHz, 전력 제한 활성은 false다.

해당 측정의 상대 IQR은 0.015%, 절대 드리프트는 0.010%다. 이상 표본과 겹친 블록은 측정 중앙값보다 약 0.0075% 길다. 이 차이로 해당 표본의 실행시간 영향을 인과적으로 추정하지 않는다. [블록 근거](affected_block.csv), [주변 센서 원문](memory_sample_context.csv)을 보존했다.

현재 분석기는 메모리가 정확히 6801인지 비교한다. 이 표본 때문에 측정별 `observed_mismatch:clocks.mem`와 전체 구간 `worker_mismatch:clocks.mem`가 발생했고, 120개짜리 마지막 구간의 저장·검산 후 다음 구간 전에 중단됐다.

NVML의 해당 클럭 조회 API는 MHz 단위 정수값을 반환한다. 이는 반환 형식에 관한 근거이며, 이번 1 MHz 차이가 반올림 때문이라는 증거나 허용 오차 ±1 MHz의 보증은 아니다. [NVIDIA NVML 공식 문서](https://docs.nvidia.com/deploy/nvml-api/api/group__nvmlDeviceQueries.html). 기록 원인은 미확정으로 남기고, 원본 판정이나 허용 기준을 사후 변경하지 않았다.

## 재개와 복구 범위

현재 결과 폴더는 저장된 메모리 불일치 때문에 `require_clean_resume`에서 `resume refused`로 차단된다. 같은 명령을 그대로 재실행하거나 `--retry-failed`를 붙여 해결할 수 없다. 원본 FAIL이 아니라 센서 REVIEW이고, 구간 전체에도 이상이 남아 있기 때문이다.

검산한 보수적인 복구안은 다음과 같다.

| 구분 | 측정 수 | 처리 제안 |
|---|---:|---|
| 정상 구간 0~13 | 1,680 | 원래 기록과 출처를 유지해 재사용 |
| 이상 구간 14 | 120 | 구간 전체 재측정, 기존 기록도 보존 |
| 아직 수집하지 않은 조건 | 1,800 | 기존 계획 순서로 추가 수집 |
| 복구 시 새로 수집할 합계 | 1,920 | 코어 720·메모리 6801 MHz·70 W와 기존 기준 유지 |

정상 1,680개와 재측정/미수집 1,920개를 합치면 기존 3,600개 task 목록과 정확히 일치한다. [복구 대상 목록](recovery_queue_proposed.csv)에 근거를 남겼다. 이는 복구 범위 검산이며, 기록 이관·복구 실행본·GPU 재실행은 아직 수행하지 않았다. 별도 복구 단계에서 원본 ZIP과 모든 시도를 보존하고, 재시작에 따른 worker 변경을 기록해야 한다. 단순히 문제 행을 삭제하거나 기존 결과를 통과로 바꾸는 방식은 쓰지 않는다.

예열과 검산을 포함한 추가 시간은 약 2~3시간을 계획할 수 있으나 새 이상·중단 가능성을 포함한 완료 보장은 아니다. 같은 1 MHz 기록이 반복될 경우 센서 의미와 판정 범위를 별도로 검토해야 한다. 현재 자료만으로 코어를 더 낮춰야 한다고 판단하지 않는다.
