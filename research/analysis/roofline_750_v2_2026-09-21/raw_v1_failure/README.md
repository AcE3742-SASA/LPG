# 750 MHz 통합 Roofline 본측정

2026-09-21 사용자 승인: 약 1–2시간을 들여 기존 16개 커널·여러 크기·5회 반복을 측정하고, 메모리 대역폭도 같은 실행에서 다시 측정한다. 기존 설치를 재사용하며 측정 목표는 SM 750 MHz·메모리 6801 MHz·기존 전력 한도 70 W다. 이 패키지를 준비하면서 원격 GPU 실행이나 설정 변경은 하지 않았다.

## 실행

다른 GPU 측정이 끝나고 정리된 뒤 이 폴더 전체를 Ubuntu `/home/eu/roofline_750_v1/`에 둔다. SSH 단절에 대비해 기존 tmux 세션에서 실행한다. 스크립트가 tmux를 새로 만들지는 않는다.

```bash
bash /home/eu/roofline_750_v1/run.sh
```

처음 sudo 암호를 요구할 수 있다. 다른 GEMM 작업의 GPU UUID 공유 잠금 또는 계산 프로세스가 있으면 설정 전에 중단한다. GPU 0의 기존 70 W·여유 VRAM 8 GiB 이상, 두 도구 소스 커밋·청결 상태·바이너리 해시와 센서 필드를 확인한다. 통과하면 750/6801 MHz를 다시 설정한다. 자식 CUDA 프로세스는 확인한 GPU UUID에 고정한다. **종료 시 클록 고정은 유지한다.** 기존 780 자료나 다른 본수집 폴더를 덮어쓰지 않는다.

## 측정 범위

- 연산: FP32 SIMT 8개, FP16 입력/출력·FP32 누산 Tensor Core 8개. 설치된 정확한 이름·A/B/C/D 배치는 `kernels.json`에 있다. TF32·sparse·새 자료형은 포함하지 않는다.
- 행렬: M=N=K=4096, 8192, 16384. alpha=1, beta=0, batch=1, split-K=1. 입력 분포·seed·workspace=1은 기존 점검과 같다.
- 각 CUTLASS 호출: device 참조 검증, 내부 예열 10회, profiling-duration=1000 ms·최소 10회. cuBLAS 교차 검증을 통과했다는 뜻은 아니다. 값은 2MNK/시간으로 재계산한다.
- 대역폭: BabelStream CUDA float, Classic, 100회. 배열당 67108864·134217728·268435456원소, 세 배열 합계 0.75·1.5·3 GiB. Copy/Mul/Add/Triad/Dot을 모두 저장한다. 논리적 byte 수/시간이며 실제 DRAM 카운터 값과 구분한다.
- 예열 0라운드 51회는 통계에서 제외한다. 본측정 5라운드 × (48 GEMM + 3 BabelStream) = 255회다. 총 306회 = GEMM 288회 + BabelStream 18회. 본측정 GEMM은 240행, BabelStream은 75행의 커널 결과를 집계한다.
- 1–5라운드는 고정 seed로 커널·크기 순서를 섞고 BabelStream을 라운드 앞/뒤에 번갈아 둔다. 다섯 번은 같은 세션 내 별도 프로세스 실행이며 날짜·재부팅을 달리한 독립 세션 재현성은 측정하지 않는다.
- 예상 약 1–2시간은 기존 8192³ 전체 벽시계 시간에 기초한 추정이다. 16384³의 정확성 참조 계산 때문에 2시간을 넘을 수 있다. 설치·클록 상태에 따른 실측 소요시간은 결과에 저장한다.

## 판정과 결과

GPU 사용률·SM/메모리 클록·전력·한도·온도·순간 전력/열 제한 상태·누적 SW Power Cap 카운터를 50 ms 간격으로 요청한다. 기존 본수집에서 사용한 센서 필드를 재사용한다. 센서의 실제 갱신 해상도가 50 ms임을 보장하지 않으며 표본 사이의 변동까지 배제하지 않는다. 프로파일러의 device 검증·내부 예열·timing을 포함한 전체 호출 구간을 관측하므로 제한 표본을 timed GEMM에만 귀속하지 않는다.

- 설정·도구·정확성·CSV 형식·부하 클록/한도·센서 수집 실패는 후속 부하를 중단하고 원자료를 보존한다. 무부하 클록이 750/6801과 다른 것은 거부하지 않는다.
- 부하 표본에서 순간 전력/열 제한이 관측되면 해당 호출을 REVIEW로 남기고 계속 수집한다. 누적 카운터 증가는 별도 진단으로 보존하며 제한시간 비율로 환산하지 않는다.
- 각 커널/크기의 본측정 5회 중앙값·최소/최대·IQR·범위/중앙값·처음/마지막 변화를 저장한다. 5회 미확보·REVIEW 호출 포함·범위/중앙값 5% 초과는 REVIEW다. 데이터를 자동 제거하거나 좋은 값만 다시 측정하지 않는다.
- 정상 종료 0: 모든 수집·검사·반복 변동 기준 통과. 종료 2: 수집은 끝났지만 REVIEW 항목 있음. 종료 1 또는 128+신호: 실패/중단. 어느 경우든 출력된 tar.gz를 전달한다.
- `SUMMARY.txt`, `summary.csv`, `analysis.json`, 실행별 명령·로그·CSV·센서·검사·시간, 실행 코드·계획·해시를 `/home/eu/roofline_750_랜덤문자/`와 같은 이름의 tar.gz에 남긴다. 다음 실행은 새 폴더에서 시작하며 자동 재개하지 않는다.
- PASS 그룹 중 가장 높은 5회 중앙값을 경로별 천장 후보로 제공한다. 전체 수집 미완료 시 후보를 비워 둔다. REVIEW 그룹을 포함한 전체 표도 보존한다. 크기별 포화와 후보의 제한 표본·누적 카운터를 검토한 뒤 Roofline에 채택한다. 단일 최고값이나 모든 구현의 절대 물리 상한으로 해석하지 않는다.

기존 780 MHz 대역폭·연산값은 이 실행에 섞거나 클록 비례로 환산하지 않는다. 원자료 반환 뒤 750 MHz 곡선을 그린다.
