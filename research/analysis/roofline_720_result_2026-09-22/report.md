# 720 MHz 경험적 Roofline 본측정 결과

기록일: 2026-09-22. 원자료: `roofline_720_eif_37o1.tar.gz`. 현재 연구 조건은 SM 720 MHz·메모리 6801 MHz·전력 한도 70 W다. 아래 그래프는 이번 실측값으로 구성했으며 750 MHz 결과를 환산하거나 혼합하지 않았다.

- 원본 2,471파일과 압축을 보존했고, 내장 명세 2,470개의 해시와 배포 720 MHz v1의 4파일이 일치했다. 306개 실행 명령과 개별 검사 결과를 다시 확인했다. 기존 분석기로 원로그에서 재생성한 `analysis.json`, `summary.csv`, `SUMMARY.txt`는 제출본과 바이트 동일하다.

## 채택한 경험적 천장

시험한 커널·크기별 5회 중앙값 중 가장 큰 값을 경로별 기준선으로 채택했다. 이 값은 이번 도구·자료형·크기 범위에서 얻은 경험적 천장이며 모든 구현의 물리적 최대치를 뜻하지 않는다.

| 항목 | 5회 중앙값 | 범위/중앙값 | 상대 IQR | 선택 조건 |
|---|---:|---:|---:|---|
| FP32 SIMT | 6.14 TFLOP/s | 0.0070% | 0.0014% | 16384³ |
| FP16 Tensor Core·FP32 누산 | 35.02 TFLOP/s | 0.0064% | 0.0024% | 16384³ |
| 읽기 중심 대역폭 | 262.3 GB/s | 0.29% | 0.0724% | Dot, 세 배열 합계 3 GiB |

- FP32 커널: `cutlass_simt_sgemm_128x128_8x2_tt_align1`. A/B=row, C/D=column이다.
- Tensor Core 커널: `cutlass_tensorop_f16_s16816gemm_f16_256x128_32x3_nt_align8`. FP16 입력·출력, FP32 누산이다. A=column, B=row, C/D=column이다. 일반 FP32 SIMT 성능과 구분한다.
- 연산량은 2MNK/실행시간으로 재계산했다. alpha=1, beta=0, batch=1, split-K=1이다. device 참조 검증·내부 예열 10회·profiling-duration 1000 ms 및 최소 10회 설정을 유지했다.
- BabelStream CUDA float·Classic·100회를 사용했다. 각 실행은 첫 내부 반복을 제외한 최소 시간으로 대역폭을 보고하며, 별도 프로세스 5회 값의 중앙값을 집계했다. Dot의 262.3 GB/s는 논리적 읽기 byte 수에 기초한 값으로 실제 DRAM 트래픽 카운터를 직접 측정한 값은 아니다.

## 크기 및 메모리 패턴

다음은 최종 선택한 동일 연산 커널의 크기별 5회 중앙값이다.

| M=N=K | FP32 SIMT (TFLOP/s) | FP16 Tensor Core (TFLOP/s) |
|---|---:|---:|
| 4096³ | 5.94 | 33.22 |
| 8192³ | 6.09 | 34.56 |
| 16384³ | 6.14 | 35.02 |

8192³→16384³ 중앙값 증가는 FP32 0.79%, Tensor Core 1.31%다. 더 큰 행렬의 포화 여부는 미측정이다.

| BabelStream 함수 | 0.75 GiB (GB/s) | 1.5 GiB (GB/s) | 3 GiB (GB/s) |
|---|---:|---:|---:|
| Copy | 252.9 | 244.9 | 240.7 |
| Mul | 166.0 | 166.2 | 166.3 |
| Add | 244.6 | 244.9 | 243.0 |
| Triad | 185.4 | 185.6 | 185.7 |
| Dot | 255.3 | 259.8 | 262.3 |

GiB는 세 배열의 총 저장 크기, GB/s는 십진 단위다. 읽기·쓰기·연산 구성이 다르므로 Dot 천장을 모든 접근 패턴이 달성할 대역폭으로 해석하지 않는다. Dot은 1.5→3 GiB에서 0.97% 증가했다.

## 클록·전력 관측과 해석 범위

- 전체 센서 149,076개 중 부하(GPU 사용률>0) 표본 148,758개 모두 720/6801 MHz·70 W다. 사용률 100% 표본은 143,737개다. 메모리 810 MHz로 기록된 12개 표본은 모두 사용률 0%여서 사전에 정한 부하 판정 대상에서 제외됐다. SM 표본은 무부하를 포함해 모두 720 MHz다.
- 온도 35–62°C, 최대 전력 50.3 W다. 센서 요청 간격은 50 ms이고 실행 내 최대 실제 표본 간격은 158 ms다. 표본 사이의 순간 변동까지 배제하지 않는다.
- 조회한 순간 SW Power Cap·SW Thermal·HW Thermal 상태는 전체 표본에서 비활성이었다. 관측 구간은 프로파일러의 정확성 검증·예열·timing을 포함하므로 timed GEMM만 분리한 진단은 아니다.
- 시작/종료 스냅샷의 SW Power Capping 누적 차이는 5,541.5초, 각 호출 끝−시작 차이 합은 5,487.8초다. 두 값은 관측 구간이 다르다. 순간 상태·클록과 누적 카운터의 불일치는 미해결이며, 이를 timed GEMM 제한시간·제한 비율이나 드라이버 오류로 단정하지 않는다.
- SW Thermal·HW Thermal·HW Power Braking 누적 차이는 모두 0이다. PASS는 사전에 정한 실행·정확성·관측 클록·반복 변동 검사를 통과했다는 의미다. 누적 카운터의 해석 문제가 해결됐다는 의미는 아니다.

## 보존한 750 MHz 결과와 비교

| 각 실행의 선택된 경험적 기준선 | 750 MHz | 720 MHz | 변화 |
|---|---:|---:|---:|
| FP32 SIMT (TFLOP/s) | 7.05 | 6.14 | −12.91% |
| FP16 Tensor Core (TFLOP/s) | 40.26 | 35.02 | −13.02% |
| Dot 대역폭 (GB/s) | 263.0 | 262.3 | −0.25% |

설정 클록 감소는 4.00%지만 연산 처리율 감소는 약 13%였다. FP32의 최고 커널은 750 MHz의 nt에서 이번 tt로 달라졌다. 동일 커널·동일 크기끼리 비교해도 FP32 12.67–13.65%, Tensor Core 11.55–13.02% 감소했다. 따라서 클록 비례 환산으로 이번 결과를 대체하지 않는다.

두 실행의 GPU UUID, 도구 커밋·바이너리 해시, 기록된 CUDA 환경은 일치한다. 별도 시간대의 두 실행이므로 감소분 전부를 SM 클록 변화 하나의 인과 효과로 확정하지 않는다. 63개 동일 조건의 전체 비교는 `comparison_750_720.csv`에 있으며, 차이의 원인을 밝히는 새 GPU 진단은 수행하지 않았다.

## 그래프 정의와 저장 파일

I를 FLOP/byte, P를 TFLOP/s로 두면 표시용 식은 다음과 같다. 실제 그림과 CSV는 반올림 전 값을 사용했다.

```text
FP32: P(I) = min(6.14, 0.2623 × I)
FP16 Tensor Core: P(I) = min(35.02, 0.2623 × I)
```

교차점은 FP32 23.4, Tensor Core 133.5 FLOP/byte다. 대상 응용 커널의 실측 OI 점은 추가하지 않았다. 크기별 그림의 오차 막대는 5회 관측 최소–최대 범위이며 신뢰구간이 아니다.

- `roofline_720.png/.pdf/.svg`: 720 MHz Roofline. PNG 300 dpi, PDF·SVG 벡터 형식.
- `size_scaling_720.png/.pdf/.svg`: 커널·행렬 크기별 처리율과 다섯 메모리 패턴의 대역폭.
- `roofline_parameters.json`, `roofline_curve.csv`: 반올림 전 기준선·단위·교차점·곡선 데이터.
- `recomputed/summary.csv`: 63조건의 중앙값·최소/최대·IQR·변동 폭. `runs.csv`: 전체 306회 실행 구간.
- `audit.json`, `raw/manifest.json`: 검산 결과와 원본 해시. `raw/`: 압축을 포함한 원자료 보존본.
- `comparison_750_720.csv`: 같은 커널/함수·크기의 두 실행 중앙값 비교.
- 재검산은 `python3 -B audit.py`, 그림 재생성은 `python3 -B plot.py`다. 보존한 로컬 `roofline_720_v1` 분석기와 기존 matplotlib/numpy를 사용하며 새 GPU 작업은 실행하지 않는다.
