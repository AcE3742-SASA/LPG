# 720 MHz 재측정 실행본 검증

2026-09-30 사용자가 전수 결과의 REVIEW 5,160건 재측정을 승인했다. SSH 서버는 응답했으나 자동 인증이 되지 않았고, 사용자는 실행 명령을 직접 입력하는 방식을 선택했다. 이 폴더의 검증은 로컬 CPU에서 수행한다. GPU 재측정은 아직 시작하지 않았다.

## 실행본

[재측정 ZIP](../../remeasure_720_review_2026-09-30_v1.zip)의 `remeasure_720_v1` 폴더를 Ubuntu `/home/eu/gemm-research/scripts/` 아래에 둔다. [실행 안내](../../remeasure_720_v1/README.md)의 한 줄 명령을 기존 tmux에서 실행한다.

`run.py`와 `analyze_sweep.py`는 기존 v2와 바이트 단위로 동일하다. 측정 프로토콜은 유지하고, 정상 결과에서 사라지는 Graph 설정 14개만 원본 묶음 수로 추가 고정했다. 새 준비기는 검증된 원본 ZIP 전체를 보존하고, 정상 기록 108,222개와 그 근거만 별도 DB 및 폴더로 가져온다. 기존 원본과 다른 실행본은 수정하지 않는다.

## 확인한 구성

- 계획 113,382건 중 원본 PASS 108,222건을 가져오고 REVIEW 5,160건만 미수집 상태로 둔다.
- 재측정 대상의 ID, 순서, seed, split을 유지한다. fresh holdout은 798건이며 시간값을 공개하지 않는다.
- 전체 Graph 선택 12,144개의 digest는 `66d072c65eb95e031a9bb43ac5b93c33e6f8364336fda5503fe3782f153024f6`이다.
- 정상 903구간을 가져오고 문제 43구간은 원본 ZIP 안에 보존한다. 가져온 근거 112,791파일을 해시로 확인한다.
- 진행 표시는 재측정 0/5,160, 전체 108,222/113,382에서 시작한다. 기존 진행률 파일만 읽으며 GPU나 DB를 조회하지 않는다.

## 검증 상태

실제 원자료를 이용한 준비·재개 및 CPU 센서 재계산을 모두 통과했다. 정상 903구간의 108,222건은 PASS, 미수집은 정확히 5,160건이며 회차 간 추가 플래그는 0건이다. 준비를 반복해도 기록이 중복되지 않고, 실행 중 잠금·다른 ZIP·관련 없는 출력 폴더·변조된 근거 파일은 거부한다. 원본 ZIP의 해시도 처음과 같다. [최종 검산](validation.json)에 기록했다. 이때 `INCOMPLETE`는 승인된 5,160건을 아직 GPU에서 수집하지 않았다는 뜻이다.

기존 측정기의 안전·재개 검사 8개와 ZIP 배포 검사는 통과했다. 정확한 720 MHz 선택, 클럭 이탈 표시 후 계속, 정확성·센서 오류 시 중단, 실패 시 클럭 해제, 시간 분모·정확성 데이터 손상 거부, 미수집 task만 재개, manifest·잠금 검사, 전체 범위 보존을 확인했다. [배포 검산](delivery_validation.json)은 ZIP CRC, 추출본 9파일의 바이트 일치, 의존성 100파일 해시, 추출본 계획, Bash 문법, 준비 실패 시 GPU 실행 방지, 기존 tmux 사용, REVIEW 종료 코드 2와 종료 후 압축 경로를 포함한다.
