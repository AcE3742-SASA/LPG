# 720 MHz 복구 실행본 검증

사용자가 정상 1,680측정 보존 후 1,920개 추가 수집과 진행률 표시를 요청했다. 기존 720/6801 MHz·70 W, 측정기 소스 9파일과 의존 74파일, 3,600개 계획과 판정 기준을 유지했다.

실제 반환 ZIP을 입력으로 배포 ZIP 추출본의 CPU 검사 7항목을 통과했다. 정확한 prefix 이관·대기 목록, 중복 없는 재실행, 잘못된 ZIP/기존 경로/영수증 거부, 이관 근거 변경과 원본 실패의 재개 차단, 진행률, 기존 실행기 위임과 종료코드 2, Ctrl+C 전달·정리와 종료코드 130을 확인했다. 새 GPU 실행은 없다.

원본 본측정 2,020파일과 점검 195파일의 최종 해시는 보존 목록과 일치한다. 로컬 점검 연결로 제거됐던 SQLite sidecar 두 파일은 변경 없는 원본 ZIP의 바이트로 복원했고 DB 본체 해시는 변하지 않았다. 기존 실패 구간과 1,800시도 전체는 복구 결과의 recovery/source_run.zip에 보존된다.

진행률은 기존 progress.json만 20초마다 읽고 전체·추가 수집 완료 수와 남은 수를 표시한다. 46.7%에서 시작하며 종료 시 마지막 상태를 다시 표시한다. 100%는 기록 수집 완료이고 검산·클럭 해제·압축 완료는 별도 확인한다. 정확 일치 기준과 미해결 카운터는 유지한다.
